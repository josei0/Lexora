Lexora — AI Legal Assistant Platform

Peta Perencanaan Proyek

Dokumen perancangan lengkap: arsitektur, roadmap, keputusan teknis, dan panduan eksekusi untuk platform AI hukum Indonesia.

MVP — Hukum Indonesia Next 16 + Go + PostgreSQL Qdrant + Claude localhost deploy

Arsitektur

Stack & Pembagian Tugas

Frontend

Next.js 16

React 19, Tailwind v4, shadcn base-nova, bun. Design system dari client — navy, emas, cream, Inter + Playfair.

Backend

Go — Clean Architecture

REST + SSE streaming. Delivery → Usecase → Domain ← Repository. OpenAPI spec-first.

Infra

Docker Compose

PostgreSQL 17, Qdrant 1.12. App jalan native: make run + bun run dev.

AI

Claude Only

Satu client, model = parameter. Demo: Haiku. Pro: Sonnet ($17/seat). Premium: Opus (fase 2).

Vector

Qdrant + nomic-embed-text

Embedding lokal dim 768. Collection kb_<org_id> dan docs_<org_id>. Metadata citation di payload.

Pipeline

Go Background Worker

Ingestion KB via goroutine: Upload → OCR → Chunk → Embed → Qdrant. Chat/RAG tetap di Go langsung. n8n masuk update besar #1 untuk ingestion sumber eksternal terjadwal.

Roadmap

Fase Pengerjaan

Fase 0

Fondasi

docker-compose up, backend :8080, frontend :3000, landing render, super admin ter-seed.
DoD: 4 cek infra lolos — postgres, qdrant, backend /healthz, landing localhost:3000.
Fase 0.5 — paralel

Lokalisasi Landing

Landing + /platform tampil bahasa Indonesia, konteks hukum ID. Tidak blokir backend.
DoD: lang="id", semua copy ID, referensi hukum US diganti (UU, PP, Putusan, PKPU).
Fase 1

Auth & Multi-tenant

Login lewat UI, data ter-scope per org, isolasi tenant terverifikasi. JWT access 15m + refresh rotation, argon2id.
DoD: login berhasil; org admin bisa tambah user; request lintas-org gagal (1 test wajib).
Fase 2

Knowledge Base & Ingestion

Upload PDF/DOCX/TXT → Go worker goroutine proses → terindeks di Qdrant. Client sediakan 2-3 PDF hukum contoh.
DoD: upload 1 dokumen nyata → documents.status=indexed, vektor muncul di Qdrant dashboard.
Fase 3

Chat + RAG + Citation

Tanya pertanyaan → jawaban streaming + citation sumber. Bahasa jawaban ikut bahasa pertanyaan (default ID).
DoD: jawaban streaming + minimal 1 citation benar; token_usage tercatat.
Fase 4

Subscription & Dashboard

Billing tier Demo/Pro, limit token soft/hard, dashboard statistik, export PDF/Word, panel admin.
DoD: limit token bekerja; dashboard tampil data nyata; export jalan. MVP siap demo.
Fase 5

Hardening

Audit log lengkap, checklist 10-SECURITY diverifikasi, govulncheck + bun audit bersih.
DoD: semua 12 item security centang; nol critical vulnerability; siap pindah ke server.
Fase 0 +-- Fase 0.5 (paralel, kapan saja setelah 0) +-- Fase 1 +-- Fase 2 +-- Fase 3 +-- Fase 4 +-- Fase 5 Jangan lompat fase. Fase 3 tidak bisa jalan tanpa dokumen terindeks dari Fase 2.

#AncamanMitigasiLayer
1SQLiParameterized query (pgx), zero string-concat SQLrepository/postgres
2XSSReact auto-escape; sanitize output LLM; no dangerouslySetInnerHTML; CSPfrontend + header
3CSRFBearer token di header; refresh cookie HttpOnly + SameSite=Strictmiddleware/auth
4DDoSRate limit per-IP/user; body size limit; timeoutmiddleware/ratelimit
5Security HeadersCSP, X-Content-Type-Options, X-Frame-Options, Referrer-Policymiddleware, next.config
6CORSAllowlist origin, bukan *. Credentials terkontrolmiddleware/cors
7JWTAccess 15m, refresh rotation, verify exp/iss/aud, klaim minimalpkg/jwt
8IDORSelalu scope query ke organization_id + kepemilikan. Wajib test lintas-orgusecase + repo
9SSRFMVP: tidak ada fetch URL user. Fase 2: allowlist domain, blok IP internalusecase, n8n
10Credential StuffingRate-limit login, error generik, argon2id, backoff progresifusecase/auth
11Dependency Vulngovulncheck (Go) + bun audit (FE) sebelum tiap rilisdev workflow
12Encryption at Restargon2id password; secret di .env (gitignore); disk encryption di serverseluruh app
13Mass AssignmentDTO terpisah per endpoint — field sensitif (role, plan_id, is_active) tidak boleh ada di DTO user-facingdelivery/dto, handler
14Information ExposureError handler global: detail ke structured log, client dapat pesan generik saja. Jangan expose stack trace atau nama tabelmiddleware/recover, handler
15Business Logic FlawsValidasi nilai bisnis di usecase: token limit tidak boleh negatif, jumlah invoice tidak boleh nol/negatif. Negative test wajib untuk alur billingusecase/billing, usecase/subscription
16Webhook SpoofingHMAC signature wajib di setiap webhook masuk (n8n callback + payment gateway nanti). Shared secret dari .envhandler/webhook_handler
17Insufficient LoggingLog semua event kritis via slog (stdlib Go): login, upload, perubahan role, error 5xx. Jangan log password, token, atau isi dokumenpkg/logger, middleware
18Broken Access ControlRBAC eksplisit per endpoint (matriks role × aksi). Cek role DAN kepemilikan di usecase, bukan cuma "sudah login". Admin tidak baca isi chat/dokumen usermiddleware/rbac, usecase
